## 🔁 檢視循環（主對話照此跑）

```
1. 咖哩下需求
2. 召喚 專案經理 → 拆任務、列交付項
3. 召喚 執行團隊（依任務：全端/設計/QA/創意）→ 產出交付物
4. 依「檢視觸發矩陣」召喚相關檢視團隊角色 → 各回 VERDICT
5. 任一 FAIL 含 🔴 → 彙整所有 🔴 退回執行團隊 → 改 → 回步驟 4
   （只重跑 FAIL 或受改動波及的審查官，省 token）
6. 全角色 VERDICT: PASS → 上呈 主協調者
7. 主協調者（化身咖哩）方向＋品質終審 → GO 整理成果交真人咖哩
                                     → NO-GO 退回並說明理由
```

**收斂規則**：🔴阻擋（必改才放行）/ 🟡建議（記 backlog 後做）。只有 🔴 擋交付；只剩 🟡 由主協調者裁定。避免無限循環。

## 📤 統一檢視輸出契約（每個審查官結尾固定格式）

```
## 檢視報告 — [角色名]
[🔴/🟡] 檔案:行 — 問題 — 建議改法
[🔴/🟡] ...
VERDICT: PASS
（或）VERDICT: FAIL (2🔴, 3🟡)
```

- 全角色 `VERDICT: PASS` → 上呈主協調者
- 任一 `FAIL` 且含 🔴 → 彙整 🔴 退回執行團隊
- 只剩 🟡 → 主協調者裁定（放行＋記 backlog，或要求順手改）

## 📌 已學習教訓（從漏抓的 bug 累積，全團隊必讀）

> 咖哩抓到、團隊漏掉的，記在這。重點：**程式碼層正確 ≠ 業務正確**。審查時拿真實樣本資料＋業務規則對，不要只讀程式碼。

1. **跨期區間邏輯**（2026-06-28，代碼審查官漏）：日期/時間篩選只比對單一日期 → 跨多天施工（6/1~6/30）在中間日 6/15 不顯示。**檢查點**：跨多天/跨夜/跨月資料在區間內每一天是否都正確顯示。
2. **欄位語意錯置**（2026-06-28，代碼審查官漏）：上傳工具把「分頁名」寫進「備註」欄 → 對不上日期、變雜訊。**檢查點**：欄位裝的內容符不符合該欄用途；顯示給使用者的資料是否真有意義。
3. **清整列要涵蓋所有欄**（2026-06-28，已修）：去重只搬 A~M，N/O（備註、狀態）錯位＋留空殼列。**檢查點**：清/搬列務必含所有有資料的欄，包含無標題的狀態欄。

> 這三類都是「不會崩潰但行為錯」的業務 bug。**領域知識的最終把關是咖哩**，但審查官要主動拿真實情境去問「這樣對嗎」。
